BUILD LOG / PRODUCT JUDGMENT

展示产品，
也展示判断过程。Showing products,
and the judgment behind them.

这里不记录每一次代码修改，而是记录哪些能力被留下、哪些方向被放弃，以及为什么。

BL

WHY SHOW THE PROCESS

不是流水账，
而是判断留下的痕迹。Not a running diary,
but traces left by decisions.

Meow Forge 的产品来自真实使用，也经历删减、改名、重构和放弃。Build Log 只展示已经形成结论、并能帮助外部理解产品的判断。

仍在摇摆的内部实验、无意义的版本细节和未经验证的承诺，不放在这里。

001

PRODUCT STRATEGY

Brain2：从私人控制系统，到可以被别人接手的产品。

OBSERVED / 观察

内部系统可以运行，但外部用户难以理解入口、治理、交接与维护之间的关系。

KEPT / 保留

控制系统、治理规则、任务与事件、Agent 协作以及写回机制。

DROPPED / 放弃

把 Brain2 简化成普通知识库，或只用“一次性 RAG”解释它。

RESULT / 结果

把产品边界、交付组成和最低可行接入路径放到首位。

002

VISUAL SYSTEM

Meow 系列：同一家族，但不住在同一个房间。

OBSERVED / 观察

Forge、Brain2 与 Meowdesk 的角色不同，强行统一视觉会抹掉产品性格。

KEPT / 保留

共同的品牌人格、几何语言和亲缘关系。

DROPPED / 放弃

用同一套配色与组件给所有产品统一换肤。

RESULT / 结果

Forge 负责筛选与展示，Brain2 强调控制系统，Meowdesk 保留工作台气质。

003

HOMEPAGE / v0.7

把 Build Log 移出首页，让产品重新成为主线。

OBSERVED / 观察

首页同时承担产品展示和完整开发叙事，会分散访客对产品价值的注意力。

KEPT / 保留

顶部 Build Log 入口，以及经过编辑的产品判断记录。

DROPPED / 放弃

在首页用大面积板块展示内部构建过程。

RESULT / 结果

Build Log 成为独立页面；首页只讲品牌、产品、Shizuku 与合作入口。

THE NEXT JUDGMENT

只有形成结论的判断，
才会被写进这里。Only decisions that have reached a conclusion
belong here.

后续条目会围绕真实产品边界、用户体验和交付方式持续增加，而不是追求更新频率。
